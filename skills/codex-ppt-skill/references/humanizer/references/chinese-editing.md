# 中文编辑参考

本文件补充上游 26 类规则。借鉴 Humanizer-zh 的中文示例、核心规则速查、快速检查清单与五维编辑自评；保留本地版本的中文语体、长文段落与直接交付偏好。以下示例均重新编写，不授权补充输入以外的事实。

## 核心规则速查

- 直接表达有信息的内容，删除空泛的开场和意义宣告。
- 根据逻辑调整句子和段落，不人为凑三项，也不为躲避三项而删成两项。
- 让长短句随内容变化。保留必要解释、真实转折和作者有意的反复。
- 用原文已有的细节替代套话。缺少依据时简化表述、保留不确定性，或提示作者补充；不补编数字、采访、引用或个人经历。
- 保留合适的文体。技术和学术文字可以中性、严谨；个人文章可以保留情绪与幽默，但不能替作者编造体验。
- 回复已有上下文的消息时先给结论，不复述对方已经说明或双方已经确认的背景。只保留会影响判断或后续行动的新信息。

## 中文常见问题与例外

| 关注表达 | 何时修改 | 应保留的情况 |
|---|---|---|
| 首先、其次、最后、此外、综上所述 | 连续出现但没有组织信息的作用 | 操作步骤、真实递进、正式摘要所需的总结 |
| 充分、全面、深入、显著、持续、进一步 | 只增加语气，没有范围或依据 | 有统计依据的“显著”、真实持续过程、准确程度描述 |
| 赋能、助力、打造、闭环、抓手、生态、矩阵 | 遮蔽谁做了什么、产生什么结果 | 数学矩阵、生态学、反馈闭环等实际领域概念 |
| 具有重要意义、标志着、彰显、开启新篇章 | 原文未说明重要性或转折依据 | 有事实支撑的历史转折、用户明确要求的仪式性文字 |
| 不仅是……更是……、不是……而是…… | 为普通观点搭建空洞对比 | 纠正读者可能的误解，或两端都有必要信息 |
| 精准高效、协同联动、提质增效 | 四字表达堆叠，不能说明具体行动 | 作者惯用的成语、正式术语、准确简洁的四字表达 |
| 未来可期、意义深远、值得期待 | 结尾重复赞美，没有新内容 | 祝辞、致辞、宣传语中明确需要的情绪表达 |
| 当然可以、你说得太对了、希望对你有帮助 | 聊天套话被混入最终文稿 | 信件中的称谓、问候、落款及真实交流需要 |
| 如下表所示、本文整理自、以下内容按负责人排列 | 读者能直接看出布局，或方法说明不影响使用 | 来源链接、会改变读者判断的限制、无法从页面看出的约定 |
| 先复述问题、诊断和证据，最后才给决定 | 回复对象已经知道这些背景 | 独立文章、首次说明问题、读者看不到前文的场景 |

这些是编辑线索，不是词语禁用表，更不是判断作者身份的证据。孤立出现的连接词、破折号、三项列举、正式词汇和完整格式通常无需修改。

## 文体与中文表达

- 文章、心得、实验报告优先使用完整段落。按内容决定小标题和列表，不把每句话拆成一个要点。用户要求清单时照常列出。
- 工作汇报保留主体、行动、时间、进度和困难，删掉没有依据的成绩拔高；不把正式汇报改成网络口语。
- 学术与技术文本保留限定条件、否定、比较对象、数量单位、引用和术语。没有统计依据时不能把“有所变化”改成“显著提升”。发现原文证据不足可标出或收窄措辞，不擅自修正数据。
- 个人文字保留具体经历、犹豫、偏好和不完全规整的节奏。没有作者提供的经历时，不添加“我试过”“上周朋友说”等细节。
- 常用 API、LLM、prompt、repo、PR、token 等术语可保留；不强行译名或反复换同义词。主语已清楚时，中文省略主语是正常表达，不必照搬英文主动语态规则补“你”或“系统”。
- 使用中文标点，保护代码和原样引用中的字符。破折号、引号、加粗和列表按用途判断，不机械删除；作者样本和用户格式要求优先。
- 中文夹杂英文时，保留词典固定使用连字符的词，例如 `third-party` 和 `cross-functional`；不要为了形式统一机械拆开。

## 中文改写示例

### 工作汇报：用已有事实说明变化

原文：本月我们持续深入推进流程优化，全面赋能团队协同。审批环节从五个减少到三个，平均处理时间从四天缩短到两天，充分彰显了提质增效的重要成果。

改写：本月我们将审批环节从五个减到三个，平均处理时间从四天缩短到两天。

理由：保留时间、行动与两组数据，删除无法单独验证的评价。

### 实验报告：保留有限结论

原文：值得注意的是，在本次 30 个样本的测试中，方案 A 的平均耗时为 2.1 秒，方案 B 为 2.4 秒。这一结果充分彰显了方案 A 的卓越性能，但尚未进行统计显著性检验。

改写：本次测试包含 30 个样本，方案 A 的平均耗时为 2.1 秒，方案 B 为 2.4 秒。方案 A 在这次测试中平均耗时较短，但尚未进行统计显著性检验。

理由：删除“卓越”的拔高，保留样本范围、全部数值和未检验的限制。

### 产品文案：没有具体信息就不补编

原文：此次更新为用户打造了全方位的卓越体验，标志着产品迈入全新阶段。

改写：产品已更新。

可选说明：原文未提供更新内容；如需说明价值，请补充实际改动。

理由：不能凭空添加“离线模式”“速度提升 30%”或用户反馈。空泛宣传不能改写成无来源的具体承诺。

### 个人随笔：保留原有感受

原文：周六我在旧书店待了两个小时，最后没买书。不可否认的是，这不仅是一次逛店，更是一场与自我的深度对话。其实我只是喜欢那里没人催我。

改写：周六我在旧书店待了两个小时，最后没买书。我只是喜欢那里没人催我。

理由：保留时间、经历与偏好，去掉套用的升华；“最后”在这里表达顺序，保留。

### 技术说明：必要的三项与术语应保留

原文：首先，API 支持 JSON、CSV 和 TSV 三种格式。其次，请求失败时返回错误码。此外，超时后可以重试一次。

改写：API 支持 JSON、CSV 和 TSV 三种格式。请求失败时返回错误码，超时后可以重试一次。

理由：删除机械衔接，保留三种格式、失败行为与一次重试的限制。

### 对话回复：结论放在已知背景之前

原文：你前面提到这次只改账户 A 的导入流程，也确认公共导入器还被其他账户使用。我检查了公共导入器和历史数据，改公共逻辑需要补测其他账户，还要清理已有错误记录。因此，我建议这次先保留账户 A 的修复，另开任务处理公共导入器。

改写：这次先保留账户 A 的修复，另开任务处理公共导入器。修改公共逻辑还需要补测其他账户，并清理已有错误记录。

理由：对方已经知道任务范围和公共代码背景，回复只保留决定及影响决定的新信息。若这段文字脱离对话单独发布，则需要补回必要背景。

### 不需改写的反例

“首先断开电源，再拆下外壳，最后更换保险丝。”步骤顺序有用，应保留。

“这个矩阵不可逆。”矩阵是数学术语，应保留。

“结果提示两者可能有关，但目前无法确定因果关系。”限定语承载证据边界，应保留。

“这不是付款成功通知，而是付款申请已收到的确认。”对比纠正实际误解，应保留。

## 交付前检查

先核对事实与范围，再检查文风；自然程度不能抵消事实错误。

- 人物、数字、日期、单位、来源、链接、否定、排序、同时性和比较对象是否保留？是否新增未提供的经历或承诺？有问题先修复。
- 是否把“可能”改成了确定结论，把局部结果扩大到普遍结论？是否遗漏真实困难或限制？
- 是否因禁词、段落数量或三项列举而过度修改？必要步骤、定义、清单和作者习惯应保留。
- 是否仍有空泛开场、重复升华、机械过渡、刻意短句和套话结尾？按段落逻辑修改，不只替换词语。
- 是否符合作者和文体？中文读起来是否像翻译稿？Markdown 与 Obsidian 结构是否完整？
- 回复是否重复了对方已经提供的背景？决定和下一步是否被诊断过程埋在最后？

借鉴 Humanizer-zh 的五维自评，检查直接性、节奏、读者所需解释、自然程度、精炼度。默认内部检查即可；用户要求评分时，逐项说明依据与待改处。评分是编辑判断，不能声称某个分数证明人类创作、已去除全部 AI 痕迹或可以通过检测器。
