# 交互与进度

默认按用户已明确的制作请求完成工作。大纲、风格和内部样页仍要准备与检查，但这些可逆步骤不自动成为用户审批门。

## 两种协作方式

- `delivery`（默认）：简要说明合理假设后继续；只在缺失信息会改变事实、用途或关键输出时追问，同时继续独立工作。
- `guided`：用户要求“先给大纲”“样页确认后再做”等，才在对应节点等待。合并已经确定的风格、页数、素材与后端信息，不重复确认。

不要把样页存在、内部 QA 通过或等待时间经过写成 `user_approved`。现有图片脚本中的 `sample_approved` 字段只用于用户实际确认的样页。内部样页可记录为 `sample_reviewed`；通过常规 `record_slide_result.py` 记录其结果，别伪造批准。

已选择的图片后端要保持一致；缺少该后端的必需能力时先说明具体影响。是否能并行影响耗时，不改变质量标准。只有环境允许且授权委派时才启动子 agent。

用有实际文件支持的进度：材料与内容计划、样页检查、生成、最终验证、交付。不要为报告进度而创建无用占位文件。

## 背景选择节点

用户说“让我选背景”即进入 background=choose，即便其他工作使用 delivery，也必须等待其真实选择。先展示同内容的实际预览，再记录选择；可同时继续独立的证据检查。参见 [背景选择](background-selection.md)。
