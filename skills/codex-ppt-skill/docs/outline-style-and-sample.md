# 大纲、视觉与样页

交互方式以 [交互与进度](workflow-gates-and-progress.md) 为准。

## 页级计划

任务与项目流程使用 `presentation-plan.json` 管理要求、证据和页号；需要展开叙事时，`outline.md` 为每页记录：页码、页面用途、主信息、支持证据、版式关系、必需素材、来源和需要用户看到的限制。封面可用主题名；结果页可用证据支持的结论；定义和流程页不必硬写成“洞察”。

不要机械要求 3–5 个要点。时间变化可用趋势图，同组比较可用横向条形图，架构可用有明确连接关系的图。数据只在一份内容包中维护，其他呈现引用它。

## 视觉系统

用户给参考 PPT/PDF/图片时，先渲染或查看代表页，再提取：页面比例、标题位置、字号层级、字体、颜色、留白、图片裁剪和信息密度。单凭 XML 或风格名称无法判断视觉。

没有参考时，选择适合用途的一组规则并说明。需要用户挑选风格时展示实际预览，不只给抽象名称。原有 `references/*.md` 都可用作灵感，不能让内容硬挤模板。

同一套稿保持色彩与字体体系，按内容改变构图。避免让所有页都变成等宽卡片或同一排图标。整套短稿不必机械凑固定数量的版式。

## 样页

选最有代表性的内容页，优先覆盖长中文标题、图表标签或必需图片。检查它在最终显示尺寸的阅读效果，修正后用于全稿风格参照；不要只检查漂亮封面。

`guided` 模式等待用户指定的样页确认；默认模式内部查看后继续。图片式路线记录实际 backend/tool/mode、输入图像、prompt、size/quality（工具提供时）、样页路径；不根据产品名猜模型或工具能力。后续只参考其风格，不复制每页的构图。

保存可复用风格时参见 [风格库](style-library.md)。
