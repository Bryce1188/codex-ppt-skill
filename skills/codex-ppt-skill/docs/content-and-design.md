# 内容、证据与视觉表达

## 内容包

先记录用户目标、受众与资料范围。每页用一份内容包说明 `role`、`main_message`、`evidence`、`sources`、`required_assets`、`layout_intent`。图表数据、表格数据和来源放在结构化 `data` 中，版式通过键引用；改一个数据集后同步重算标题中的比例与备注。

结果、单位和比较口径成组保留。例如 80 分钟降为 35 分钟，减少 45 分钟，降幅 56.25%；不能称为“提高 56%”而不说明指标。示例或假设明确写在对应页，不以备注代替必要披露。

标题服务于页面：结果页表达有支持的发现，背景页直接命名主题。将“赋能、全方位提升、打造闭环”等空泛词换成具体对象、变化和证据。不要为凑三条而填充内容。

## 由内容选择构图

| 阅读任务 | 常用表达 | 检查点 |
| --- | --- | --- |
| 比较数量 | 原生横向条形图 | 同一单位，零基线，顺序有意义 |
| 展示变化 | 趋势图或前后对比 | 时间一致，区分百分点与百分比 |
| 分析组成 | 堆叠柱或简表 | 合计口径一致，不用装饰圆环代替数据 |
| 解释流程 | 分步骤短文或可编辑关系图 | 连接有意义，标签就近，无装饰假流程 |
| 展示作品/项目成果 | 保真图片加简短解释 | 原始素材、截图时间、未实现部分明确 |
| 方案比较 | 对齐的文字列或原生表格 | 比较维度相同，不为整齐删关键差异 |

强视觉素材用于解释主题、提供证据或构成适当氛围。普通数据页可以靠信息层级与图表成立，不必每页生一张装饰图。保留图片式路线的审美自由；表格、准确图表和需编辑的文字优先用原生对象。

## 中文排版

无模板时可从 16:9、四周约 5% 安全边距开始。标题约 32–40pt、正文约 20–26pt、图注约 12–16pt，是选择起点而非统一硬门槛。本 skill JSON 坐标与 `fontSize` 用 CSS px（1pt = 4/3px），避免把 32px 当成 32pt。

选渲染环境实际存在的中文字体，记录 PowerPoint/WPS 端可能替换字体的限制。同级标题保持相近的大小与重量；容纳长内容时先改写、扩大可用区域或换构图，不悄悄省略证据。字号与文本框尺寸不能证明文字一定容纳，最终渲染必须查看。

用留白建立分组，减少碎片小字和多余边框。颜色用来指向主要信息。相邻页保持视觉系统一致，同时让重点图、解释页、对比页有不同阅读节奏。

## 同类配色、页脚与内容完整度

同类节点默认使用同一填充和边框。只有确实需要编码状态、类别或本页焦点，并且标签或图例能解释含义时，才设置不同样式；不能只是因为某个模块在中间就自动换色。本包工程白蓝配置默认只提供一种技术节点样式。

普通内容页不默认生成左下角固定说明、制作过程、验证状态或泛泛的结论。制作与工具限制写进交付说明或 QA 记录。必须让听众知道的业务限制、实验条件和演示数据状态，放在有关内容旁，用正常正文说明；来源按需要写在图注或备注。用户要求的品牌、页码、保密标记可以保留，不能把所有页脚一概当作错误。

一页一个主信息不等于只剩一句话。先检查该页是否讲清楚对象、过程或比较、支持证据，以及理解它所需的解释：

- 功能页：除截图外，交代主要操作、输入/权限条件和界面反馈；有源码依据时说明一个关键处理规则。
- 架构/流程页：除模块名字外，说明关键调用或数据流，结合一次真实操作解释处理步骤和边界。
- 数据库页：保留支撑业务讲述的字段、关系和关键约束，必要时补查询索引；不把整库字段无差别塞进来。
- 实验页：保留比较对象、设置、指标和主要发现，并解释图表中哪部分支撑结论；不能只放一张图和“效果良好”。

大块空位先判断是分组需要还是内容缺失。信息不足时回到来源补充关键细节；内容已完整但画面松散时，放大主图、缩短无用间隔或重新分配图文比例。不要用装饰卡片、重复总结或无来源数字填空，也不要用固定字数和填满比例代替阅读判断。

## 项目汇报的内容密度

总体架构回答模块职责和运行边界，一次操作流程回答处理顺序与事务或异常边界，分别成页。数据库正文保留与当前业务有关的实体、主外键、基数和约束，解释为什么这样设计；完整数据字典放附录或源文件。留白过多先检查是否漏掉证据、处理机制或取舍理由，不能通过增加字段和空话填满。可执行构图见 [版式实例](layout-patterns.md)。
