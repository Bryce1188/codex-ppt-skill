# 自动调用 Humanizer

每次制作或大幅修改 PPT，默认自动读取并应用 [Bryce1188/humanizer](https://github.com/Bryce1188/humanizer)。用户明确要求逐字保留的标题、引文和模板字段保持原样。

## 定位规则

```text
python scripts/resolve_humanizer.py
python scripts/resolve_humanizer.py --path <humanizer目录或SKILL.md>
```

顺序为：本次用户指定路径、与 PPT skill 同级的 `humanizer`、当前环境的已安装技能、随包的固定快照。显式路径无效时返回错误，不能假装使用了该版本。脚本不联网、不安装包，也不运行外部 skill 里的脚本。

读取 JSON 返回的 `skill_path` 和 `chinese_reference`。中文内容必须同时读取中文参考。脚本只负责找到真实规则；Agent 执行其中的润色流程，不能用“已运行定位器”代替文字编辑。

本机同级目录会优先命中用户维护的 Humanizer。公开安装即使没有单独装 Humanizer，也能使用 `references/humanizer/` 的快照；版本、上游提交与文件 SHA-256 见 [provenance.json](../references/humanizer/provenance.json)。快照保留原文与许可证，不每次自动拉取不固定的远端内容。更新快照时重新核对来源、许可证与散列。

## 两次文字处理

**内容轮，在排版之前。** 把页标题、正文、图注、图表标签和讲稿一并润色。先保留事实，再减少套话；按老师任务与听众知识决定解释深度。教师规定的名称、技术术语、引文、数值、单位、否定、条件与来源不可丢失。

**最终轮，在最终文件生成后。** 从 PPTX 取出真实文字与备注；图片式页面检查图中文字。检查有没有制作时新加的口号、重复结尾、压缩后丢失的限制或生硬标题。若有修改，重新导出并检查相应页面。

在工作目录的 `copy-review.md` 简短记录实际规则路径、散列、处理范围与必要的修改例子。原句已经自然时可以保留，不能为了证明润色而改写术语或人为制造差异。检查记录不放进演示正文。

## 示例

原句：本系统全面赋能课程数据管理，实现了卓越的数据分析能力。

若项目证据仅表明 CSV 读取、平均分和及格率计算，改为：工具读取 CSV，计算平均分和及格率。

如果实测结果含“仅在 12 条演示数据上检查过”，保留这句话。润色不能把它改成经过大规模验证。
