# 目录页与章节同步

支持按正文生成可编辑目录页。用户明确要求目录时必须加入；未指定时，根据篇幅、章节和听众是否需要导航决定。章节较多的工作汇报、答辩或研究报告通常适合目录；很短的演示可以直接进入正文，不为了目录压缩必讲内容。

## 生成规则

先确定正文结构，再归纳章节。一般列出几个主要章节，不把每张幻灯片标题逐项搬进目录。名称应具体、与正文对应；例如软件汇报可用“项目目标、功能展示、技术设计、结果与后续工作”，实际章节以本次内容为准。

目录通常放在封面后，计入用户要求的总页数。目录顺序以最终正文为准，不加入正文没有的章节。用户想显示页码时，使用最终章节起始页；不需要页码时只显示章节名和必要编号。默认目录是普通原生可编辑文字，不自动承诺点击跳转功能。

视觉沿用共享设计配置。同级条目保持同色同字级，采用清楚的列表、对齐分栏等构图，不自动添加异色卡片或左下角制作说明。

## 计划与同步

在 presentation-plan.json 中：

- 封面用 role: cover。
- 目录页用 role: agenda，标题可为“目录”或“汇报内容”。
- 正文和章节过渡页填写 section，值是目录中的章节名。同一章节连续出现。
- 目录的 agenda_items 由同步脚本生成，每项为 title 和 start_slide；不要手工猜页码。

先插入目录页并更新连续页号和 expected_slide_count，再运行：

```text
python scripts/sync_agenda.py --plan presentation-plan.json --out presentation-plan-synced.json
python scripts/validate_plan.py presentation-plan-synced.json
```

输出计划与原计划宜放在同一工作目录，保留相对来源路径。同步脚本不会替你推断章节，也不插入 PPT 页面；Agent 按生成的 agenda_items 制作实际目录页。它负责从已经确定的章节和页序更新条目，不覆盖现有文件。

后续增删、移动正文时，先更新页级计划，再同步目录和重新生成受影响页面。验证器会检查目录条目是否与章节顺序、起始页一致。这个检查针对计划；最终 PPTX 仍要检查目录文字、实际页序和可见页码。当前辅助脚本处理一个全局目录，局部章节导航按实际需要另行设计。
