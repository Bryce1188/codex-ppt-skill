# 需求澄清与 Superpowers 接入

## 自动发现，再实际读取

运行 `python scripts/resolve_superpowers.py`。显式指定安装位置可传 `--path <目录>`。
定位器支持同级完整技能包、Codex/Agents 已安装的完整包及拆分子技能。它只返回文件路径和校验值，不执行流程，也不安装或升级插件。

发现后读取返回的 router（如果有），以及当前阶段对应的文件：
- 开始时读 `brainstorming`，把模糊需求整理成简报。
- 复杂制作读 `writing-plans`，把简报落实为页级工作安排。
- 交付前读 `verification-before-completion`，用实际检查结果支持完成声明。
不要只运行定位器就说“已调用 Superpowers”。把实际读取的路径及应用阶段记入工作目录的 `process-notes.md`。

Superpowers 版本的确认节点可能不同，遵循实际读到的规则与宿主指令；用户明确要求的交互方式及既有授权优先。不要因为插件自带软件开发流程，就默认为普通 PPT 创建 Git 分支、测试工程或子代理。没有安装时使用下面的简化流程，明确记录“未加载 Superpowers”；不能声称它是所有 Codex 安装的内置功能。

## 简化流程与问题优先级

先读材料，提取已知项，再读 [简报提示词](../prompts/deck-brief.md)。优先解决：
1. 要向谁说明什么：老师验收、答辩解释、向客户演示，会改变叙事。
2. 硬性要求：发言时间、页数、指定模板、必讲章节与评分重点。
3. 事实缺口：成果文件、运行入口、数据版本或比较对象不明。
4. 视觉偏好：用户要求选择才等待选择；普通配色可自行决定。

问题示例：“这次汇报更侧重哪部分？A. 是否完成任务；B. 技术实现；C. 实验结果。”不要反复询问材料里已有答案。页数和讲述时间冲突时说明冲突，优先满足老师硬限制，必要时问一个取舍问题。

材料齐全时用几句话说明制作安排并继续。用户说“你决定”可决定普通版式，不能据此确认不存在的成绩、替用户选尚未看到的候选样页或绕过宿主权限。

## 组件职责

| 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Superpowers（可选增强） | 澄清、计划、检查节奏 | 生图、截图、PPT 排版 |
| Humanizer（自动加载，随包有固定快照） | 标题、正文、图注、备注两轮编辑 | 事实核验、保证通过 AI 检测 |
| 宿主 presentations | 原生对象、模板处理、导出与渲染检查 | 自动拥有所有外部应用权限 |
| imagegen（有需要且可用） | 无文字背景、装饰图、局部改图 | 重画实验图或假造运行界面 |
| 浏览器/计算机工具（可用时） | 实际打开项目、操作到目标状态并截图 | 被禁用时绕过限制 |
| document-to-markdown（可用时） | 读取任务书和资料 | 代替复杂图表的原页核对 |

不要求用户额外安装整套设计插件。需要几何可编辑的背景就用原生形状；需要图片编辑才读取可用的 imagegen skill。缺少某项能力时采用明确降级方案并保留可复用材料。
