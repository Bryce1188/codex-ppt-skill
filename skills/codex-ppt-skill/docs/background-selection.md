# 背景与样页选择

先区分“研究背景”和“页面背景”：前者是要讲的事实，应查来源；后者是视觉设计，由题材、受众、展示环境与证据决定。自动生成视觉不能替代查资料。

## 三种模式

| 模式 | 触发 | 动作 |
| --- | --- | --- |
| `auto` | 未指定偏好，或说“你决定”“自动生成” | 读相关风格参考，选择一套合适的视觉系统；内部检查代表页后继续 |
| `choose` | “先让我选背景/风格/样页” | 展示 2–3 个真实预览，用同一份内容比较；等待选择再批量生成 |
| `provided` | 用户指定图片、模板或已有风格 | 查看实际文件，按其布局与颜色处理；完整 PPT 模板进入 template 路线 |

`presentation-plan.json` 保存实际模式、预览路径和选择结果。`choose` 未选定前，`selected` 留空；收到明确回复才记录 `decision_source`。不能把超时、内部评分或推荐项当成用户选择。可以继续独立核对内容，不提前生成用户尚未选择的全稿。

## 自动匹配依据

- 课程答辩、实验结果、工程说明：高对比、安静背景、图表与原生文字为主，便于投影阅读。
- 软件与产品项目：用真实界面截图解释流程；主题视觉放在封面或少量章节页。
- 艺术、历史、展览：用有来源的作品或照片组织页面，给图片留足面积。
- 硬件、自然科学：保真结构图和实验图承载证据，生成插图只能辅助解释。

明确用户偏好优先于以上推荐。十套风格在 `references/`，读与当前题材相关的条目即可；不要通过堆叠所有风格词生成提示。

## 预览必须能帮助选择

每个候选包含风格名、适用理由、真实预览路径，说明是参考页、空白背景还是带内容样页。至少用一张包含当前长标题和代表性图表/图片的内容页比较。不能用漂亮的空白封面代表一整套稿的可读性，也不能把三张不同内容页称为同内容风格对比。

候选设计至少应在构图、图像占比、文字层级或图示组织上形成有意义的区别。只改变底色与强调色时明确称为配色比较，不把它当作完整风格比较。软件项目按 [代表页方法](software-project-report.md) 检查功能、架构与数据库内页。

提供已有图库或本 skill 的示例时，明确它是示例，不能声称是为本次任务生成的预览。用户有背景图时先检查比例和文本留白，裁剪不破坏关键主体。预览满意后固定字体、色彩和背景处理，按内容改变构图。

## 何时生成背景

有解释作用或题材需要时，用实际可用的生图工具生成无文字背景，按 [无文字背景](textless-backgrounds-and-html.md) 留出标题/正文区域。正文、图表、公式和数据标签使用原生对象。研究图与运行截图不能由生图补造。

普通数据页可使用纯色背景，画面是否有效以信息可读性判断。生图不可用时按现有素材与原生排版继续；用户明确指定必须生图且无法完成时说明局部缺失，不声称已经生成。

生成或局部修改背景时读取 [背景提示词](../prompts/background-design.md)。固定主题色、材质、光线和留白区；图像主体描述与整套风格描述分别保存。位图背景不能逐形状编辑，用户要求此能力时使用原生形状或可编辑矢量。
