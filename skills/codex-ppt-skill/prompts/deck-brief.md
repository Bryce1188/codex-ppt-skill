# 从朴素要求生成制作简报

供 Agent 在读完材料后使用。不要把整段问卷发给用户，也不要把模板当作额外事实。

> 根据用户要求、任务书和项目证据整理简报。先列出已知的受众、目的、发言时间、页数硬限制、必讲内容、资料来源、已完成成果、可编辑要求、模板与背景偏好。标注各项来自哪里。
>
> 找出最影响结果且无法从资料确认的缺项。每轮优先问一个问题，给 2–3 个易懂选项，也接受自由回答；没有关键缺项就继续。用户要求直接做时记录普通设计假设，不替用户补造项目结果。
>
> 以任务要求组织叙事，以实际证据确定结论强度。每页写出主信息、需要的证据、图像或数据形式、讲述时长和来源；结果页尽量让标题说明结果。保留任务书指定章节名。
>
> 调用 Humanizer 处理标题、正文、图注和备注。删掉无法说明具体工作的夸大词，不添加来源没有的经历、数字和成绩。
>
> 先制作代表性样页。自动模式自行检查并继续；用户要求选择时展示真实样页，等到明确选择再批量制作。原生文字与图表独立于背景。
>
> 检查每项要求是否有对应页面、每项成果是否有证据、每张截图是否来自真实项目。生成最终 PPTX，按宿主要求验证并渲染逐页查看。记录仍存在的缺口和未验证部分，再交付。

简报存工作目录 `brief.md`，仅保留影响制作的字段；详细页级计划使用 `presentation-plan.json`。局部修改时更新相关字段，不重新追问已有答案。
